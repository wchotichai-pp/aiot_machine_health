# 8. ปรับจูนและแบบฝึกหัด

**เป้าหมายของบท:** ปรับระบบให้เข้ากับเครื่องจักรจริง และฝึกอ่านผลแบบที่ฝ่ายซ่อมบำรุงต้องทำ

## ค่าที่ปรับได้

| ปรับที่ไหน | ค่า | ผลที่ได้ |
| --- | --- | --- |
| แชท / แดชบอร์ด | ความไว ต่ำ / ปกติ / สูง | ตัวคูณเกณฑ์ 2.5–5.0 / 2.0–4.0 / 1.5–3.0 เท่าของค่าปกติ |
| แชท / แดชบอร์ด | เรียนรู้ค่าปกติใหม่ | ใช้หลังเปลี่ยนชิ้นส่วน ย้ายตำแหน่งบอร์ด หรือเปลี่ยนรอบการทำงาน |
| `.env` | `ESCALATE_AFTER`, `RECOVER_AFTER` | ต้องเกินหรือกลับมาปกติติดกันกี่วินาทีจึงเปลี่ยนสถานะ |
| `.env` | `LEARN_SAMPLES` | จำนวนวินาทีที่ใช้เรียนรู้ค่าปกติ |
| `.env` | `TEMP_WARN`, `TEMP_ALARM` | เกณฑ์อุณหภูมิ (°C) |
| `.env` | `DEFAULT_WARN_RMS`, `DEFAULT_ALARM_RMS` | เกณฑ์ก่อนเรียนรู้ค่าปกติ |

แก้ `.env` แล้วรัน `docker compose up -d` ให้ gateway โหลดค่าใหม่

## แบบฝึกหัด

### 1. แจ้งเตือนเร็ว หรือแจ้งเตือนถูก

ตั้ง `ESCALATE_AFTER=1` แล้วเคาะโต๊ะใกล้บอร์ดเบา ๆ ครั้งเดียว จากนั้นตั้งกลับเป็น 3 แล้วทำซ้ำ

- [ ] บันทึกว่าแต่ละค่า แจ้งเตือนผิด (false alarm) กี่ครั้งใน 2 นาที
- [ ] อธิบายว่าในโรงงานจริง ควรเลือกแจ้งเร็วหรือแจ้งถูก สำหรับเครื่องแบบไหน

### 2. หาเกณฑ์ที่เหมาะกับพัดลม

1. เรียนรู้ค่าปกติที่เบอร์ 1
2. เปิดเบอร์ 2 และ 3 โดยไม่เปลี่ยนอย่างอื่น บันทึกค่า RMS
3. ติดเทปที่ใบพัดให้เสียสมดุล บันทึกค่า RMS ที่เบอร์ 1

| สภาพ | RMS (m/s²) | กี่เท่าของค่าปกติ | สถานะที่ระบบให้ |
| --- | --- | --- | --- |
| เบอร์ 1 ปกติ | | 1.0 | |
| เบอร์ 3 ปกติ | | | |
| เบอร์ 1 เสียสมดุล | | | |

- [ ] ระดับความไวแบบไหน แยก "เปลี่ยนรอบ" ออกจาก "เสียสมดุล" ได้
- [ ] ถ้าแยกไม่ได้ ควรแก้ที่ระบบหรือที่วิธีใช้งาน (เช่น เรียนรู้ค่าปกติแยกตามรอบ)

### 3. อ่านประวัติจาก API

ดึงข้อมูล 30 นาทีล่าสุดแล้วหาค่าสูงสุด

```bash
curl -s -H "X-API-Key: <API_KEY>" \
  "http://localhost:8000/api/machines/pump-01/history?minutes=30" > history.json
python -c "import json;d=json.load(open('history.json'))['items'];print(max(r['vib_rms'] for r in d))"
```

- [ ] ค่าสูงสุดเกิดตอนไหน ตรงกับเหตุการณ์ในแดชบอร์ดไหม

### 4. เพิ่มคำสั่งใหม่ (สำหรับผู้ที่เขียนโปรแกรมได้)

เพิ่ม intent `last_alarm` ที่ตอบว่าแจ้งเตือนอันตรายครั้งล่าสุดเกิดเมื่อไร

- [ ] เพิ่มใน `Intent` และ `parse_rules` ใน `gateway/app/commands.py`
- [ ] เพิ่มใน `SYSTEM_PROMPT` และ `RESPONSE_SCHEMA` ใน `gateway/app/llm.py`
- [ ] เขียนการทำงานใน `MachineService.execute()`
- [ ] เพิ่มชุดทดสอบ แล้วรัน `python -m pytest` ในโฟลเดอร์ `gateway`

สังเกตว่าต้องแก้ allowlist ก่อน AI จึงจะใช้คำสั่งใหม่ได้ การเพิ่มความสามารถให้ AI เป็นการตัดสินใจของคนเขียนระบบเสมอ

## คำถามท้ายบท

1. ถ้าโรงงานมีเครื่องจักร 200 เครื่อง ส่วนไหนของระบบนี้จะเป็นคอขวดก่อน
2. ข้อมูลอะไรที่ควรเก็บเพิ่ม เพื่อให้ช่างตัดสินใจซ่อมได้ดีขึ้น
3. ถ้าจะให้ AI ช่วย "อธิบายสาเหตุที่เป็นไปได้" ของการสั่น ควรออกแบบอย่างไรไม่ให้ AI สร้างข้อมูลเท็จ
